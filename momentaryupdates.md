It needs to be adaptable for the small screen, so it can be something like Stream Deck design, which we already have this application. [...] for each scenario, the same is in my Stream Deck control, we need to have separate tabs for different scenarios. First tab will be record because this is how we work: first we record. So I need record tab which gives me remote control for recording, from starting the metronome, arming each track to be recorded. This application needs to read the current session and know already existing tracks. So the purpose of this first REC is basic things: arm any track already existing, create new track, start metronome, has a transport control, and transport control also needs to have a visual part, or we call it a waveform part. But since this is a mobile phone it cannot display [all]; now we have like 20 tracks in the project open right now, which is a test project we're going to work with. [...] We need to use only one track, a scrubbing track or cueing track, one waveform of many. Also this application has few preset views. Whole track, meaning showing from the beginning to the end. And then a loop, which will zoom into the loop section which is defined in Ableton Live. When we have enabled the metronome for the person who records to listen to it, the app has this metronome part and the LED inside metronome part is blinking in the beat predefined by Ableton Live. Second tab is a session view where I can see exactly the screen as it is on my computer. Basically like a remote viewer for the Ableton only and I can see that window in full screen in my remote controller. This is one-to-one; it's just a viewer. We're using VNC for this, VNC protocol."

Plan: v1 = the REC tab (Android v1 + Mac helper v1); v2 = the SESSION tab (VNC of the Ableton window); next: MIX (solo, mute for all channels).
